# ryzen_smu 0.1.7.raphael2

## In plain words

`ryzen_smu` is a Linux driver that lets programs read the sensor table ("PM table") of AMD
Ryzen processors: per-core temperatures, clocks and voltages, package power, memory and
fabric clocks. Tools such as `monitor_cpu` and `ryzen_monitor` need it.

This release is for **Ryzen 7000 desktop (Zen 4, "Raphael")** owners, e.g. a Ryzen 7 7800X3D.
The stock `monitor_cpu` only understands Ryzen 3000 tables and refuses (or crashes) on a
Ryzen 7000. This one shows a live view of the Ryzen 7000 table.

The **kernel driver is unchanged** from [amkillam/ryzen_smu](https://github.com/amkillam/ryzen_smu)
`main` (d298366, module version 0.1.7); the changes are in `monitor_cpu`, the scripts, the
packaging and the documentation.

## What's new

- `monitor_cpu` understands PM table **0x540104** (Raphael). It shows only values that were
  checked against independent sensors: per-core temperature / clock / voltage, package power,
  IOD hotspot, FCLK, MCLK / UCLK, VSOC, VDDP.
- Correct clocks on boards with a raised reference clock (BCLK / eCLK, e.g. 105 MHz). It is
  measured automatically; `-b<MHz>` overrides it.
- `monitor_cpu -h` works without an argument (and without root), `-u<seconds>` sets the refresh
  interval, `-f` no longer crashes or reads past a small table.
- `scripts/test.py` knows all code names the driver knows (up to Strix Halo).
- `dkms.conf` works as is; the Arch package needs no extra steps for clang-built kernels
  (DKMS adds `LLVM=1` itself).
- New: Arch package, plain-English [User Guide](https://github.com/eugenesflanagin-spec/ryzen_smu/blob/raphael-release/docs/USER-GUIDE.md), CI that builds and install-tests the package in a clean Arch container.

The Raphael `monitor_cpu` change is also offered upstream as amkillam/ryzen_smu#54.

## Install (Arch Linux)

```sh
sha256sum -c SHA256SUMS --ignore-missing          # must print "...pkg.tar.zst: OK"
sudo pacman -S --needed dkms linux-headers         # headers for each kernel you boot
sudo pacman -U ryzen_smu-raphael-dkms-0.1.7.raphael2-1-x86_64.pkg.tar.zst
sudo modprobe ryzen_smu
echo ryzen_smu | sudo tee /etc/modules-load.d/ryzen_smu.conf   # optional: load at boot
```

It replaces `ryzen_smu-dkms-git` if you have it (same driver; pacman asks, answer `y`).
Other distributions: `git clone https://github.com/eugenesflanagin-spec/ryzen_smu`,
`cd ryzen_smu && sudo make dkms-install` (see the User Guide, section 3c).

## Check that it works

```sh
dkms status | grep ryzen_smu          # ryzen_smu/0.1.7.raphael2, <your kernel>, x86_64: installed
cat /sys/kernel/ryzen_smu_drv/drv_version /sys/kernel/ryzen_smu_drv/codename   # 0.1.7 and 20 (Raphael)
sudo python3 /usr/share/ryzen_smu/scripts/test.py   # ends with "Everything seems to be working properly!"
sudo monitor_cpu                      # live view, Ctrl+C to quit
```

`drv_version` stays `0.1.7` on purpose: tools built on `libsmu` require that exact string.
Everything above only reads values (`test.py` sends the harmless "get SMU version" command).

## Known limits

- The 0x540104 layout was validated on one Ryzen 7 7800X3D. Other Raphael models report the
  same table version but have not been checked.
- MCLK and UCLK are indistinguishable at a 1:1 ratio, so their order follows other tools.
- `monitor_cpu -m` (DRAM timings) uses the DDR4-era register layout; on DDR5 the values may be meaningless.
- The module is unsigned: with Secure Boot on, sign it with your own key or it will not load.
- Writing SMU commands can change voltages and clocks; only use tools you trust.
